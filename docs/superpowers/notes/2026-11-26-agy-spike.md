# Spike de Antigravity (`agy` 1.5.17) en Windows

Fecha: 2026-11-26
Versión probada: `agy 1.5.17` (`windows/amd64`), en repositorios git temporales.

## Vías evaluadas

### Vía 1: `agy -p --output-format stream-json --model <m> --dangerously-skip-permissions --sandbox`
- **Comportamiento de flags:** en `agy 1.5.17`, `-p` (`--print`) toma el prompt como valor del propio flag (`-p=<prompt>`), no como bandera booleana. Invocar `agy -p --output-format stream-json ...` falla con exit code 2 (`Error: -p took "--output-format" as its prompt`).
- **Con flags antes de `-p=<prompt>` y stdin cerrado:** dio salida por pipe (`5731` bytes), creó `hola.txt`, y devolvió `conversation_id` en el evento `init` y en `result`:
  ```json
  {"event":"init","conversation_id":"8dd5a880-db6d-41fa-a881-c3bb92705f8f","init":{"model":"gemini-4-hydrogen","permission_mode":"always-proceed"}}
  {"event":"step_update","step_update":{"conversation_id":"8dd5a880-db6d-41fa-a881-c3bb92705f8f","step_index":1,"state":"ACTIVE","step_type":"agent_response","text_delta":"OK"}}
  {"event":"result","result":{"conversation_id":"8dd5a880-db6d-41fa-a881-c3bb92705f8f","status":"SUCCESS","response":"OK\n"}}
  ```
- **Modelo inválido:** salió con código 1 e imprimió tanto en stdout (`{"event":"result","result":{"status":"ERROR","error":"invalid model selection..."}}`) como en stderr.
- **Limitación bloqueante para Weaver:** con `--input-format text` (defecto), `-p` ignora stdin y exige el prompt en `argv`, violando la restricción global de nunca pasar prompts largos por línea de comandos en Windows (~32K y escapado). Al intentar `--input-format stream-json` por stdin con un mensaje estilo Claude, falló con código 1 (`stream input message is missing the "event" field`, esquema de entrada no documentado en `--help`).

### Vía 2: `agy acp` (Agent Client Protocol JSON-RPC 2.0 por stdio) — **ELEGIDA**
Comando: `agy acp --dangerously-skip-permissions --sandbox` (con `cwd` = worktree).

- **Salida por pipe en Windows:** funciona en tiempo real por `stdin`/`stdout` JSON-RPC 2.0 (NDJSON).
- **Flujo observado:**
  1. `initialize` (`protocolVersion: 1`) → devuelve capacidades (`loadSession: true`, `sessionCapabilities.resume: {}`) e `agentInfo`.
  2. `session/new` (`{"cwd": dir, "mcpServers": []}`) → devuelve `sessionId` (UUID, p. ej. `"d1de2822-a530-4715-b41b-4c94f809da2b"`), `models.availableModels` y `modes`.
  3. `session/set_model` (`{"sessionId": sid, "modelId": "gemini-4-hydrogen"}`) → devuelve `{}` (acepta tanto `gemini-4-hydrogen` como las variantes `-low`/`-medium`/`-high`/`-xhigh`).
  4. `session/prompt` (`{"sessionId": sid, "prompt": [{"type":"text","text": "..."}]}`) → emite notificaciones `session/update` en tiempo real y termina con `result.stopReason: "end_turn"`.
  5. **Reanudación (`follow_up`):** en un nuevo proceso `agy acp`, `initialize` + `session/resume` (`{"sessionId": sid, "cwd": dir, "mcpServers": []}`) restauró la conversación (`"42"` recordado de un turno previo).
- **Fragmento real observado (`agy acp`):**
  ```json
  {"jsonrpc":"2.0","result":{"sessionId":"d1de2822-a530-4715-b41b-4c94f809da2b","models":{"availableModels":[{"modelId":"gemini-4-hydrogen-high","name":"Gemini 4 Hydrogen (High)"}],"currentModelId":"gemini-4-neon-high"}},"id":2}
  {"jsonrpc":"2.0","method":"session/update","params":{"sessionId":"d1de2822-a530-4715-b41b-4c94f809da2b","update":{"sessionUpdate":"tool_call","toolCallId":"call_7008398241754701218","name":"write_file","status":"in_progress","kind":"edit"}}}
  {"jsonrpc":"2.0","method":"session/update","params":{"sessionId":"d1de2822-a530-4715-b41b-4c94f809da2b","update":{"sessionUpdate":"agent_message_chunk","content":{"type":"text","text":"OK"}}}}
  {"jsonrpc":"2.0","result":{"stopReason":"end_turn","usage":{"inputTokens":24211,"outputTokens":302,"totalTokens":44378}},"id":4}
  ```
- **Modelo inválido:** `session/set_model` responde con error JSON-RPC `{"jsonrpc":"2.0","error":{"code":-32602,"message":"Unknown model ID: modelo-inexistente-xyz"},"id":3}` → `Classify` lo mapea directamente a `ModelUnknown`.
- **Cuota agotada:** no se pudo provocar sin agotar la suscripción real de Google AI Pro en pruebas; cualquier error JSON-RPC de `session/prompt` o salida con error en `stderr` pasa por `Classify(...)` (`quota|rate limit|exhausted|429` → `QuotaExhausted`).
- **Por qué se elige Vía 2:** el prompt completo (incluido `SystemPromptFile`) viaja por stdin en JSON-RPC (sin límite de `argv` en Windows), usa un protocolo estructurado documentado en `agy`, soporta `session/resume` de forma nativa y transmite eventos y herramientas en vivo por pipe.

### Vía 3: `transcript.jsonl` bajo `~/.gemini/antigravity-cli/brain/<conversation_id>/`
- En la ejecución de Vía 1 se verificó la creación de `~/.gemini/antigravity-cli/brain/<conversation_id>/.system_generated/logs/transcript.jsonl` (`2171` bytes).
- **Descartada como vía primaria** porque hereda el problema de pasar prompts por `argv` de `-p` y requiere vigilar archivos externos fuera del proceso hijo; queda innecesaria al funcionar Vía 2 (`agy acp`) limpiamente por stdio.

## Detección de "vacío = fallo"

En el adaptador `agy acp`, cualquiera de las siguientes condiciones se trata como `EmptyOutput` (nunca como éxito, incluso si el proceso termina con código 0):
1. El proceso termina con 0 líneas recibidas por stdout.
2. El proceso termina (EOF) sin haber respondido al request `session/prompt` (sin `result` ni `error` JSON-RPC para ese ID).
3. `session/prompt` responde `stopReason: "end_turn"` pero el texto acumulado del asistente está vacío (`""`).

RESULTADO: vía fiable encontrada — `agy acp` (JSON-RPC 2.0 por stdio).
